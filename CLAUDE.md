## 0.1 Quality gates (bug prevention — mandatory, checked in CI)
- **Tests first for rules**: every validation rule id (ORDERS_SPEC B1–B14/W1–W20, invoice checks), every parser and
  every state transition gets a failing test before the implementation; test names contain the rule id.
- **Property-based tests** (`hypothesis`) for `parse_decimal`, `normalize_code`, unit/price-per conversion (never any
  packaging rounding — DECISIONS D17), filter builder (no unsafe value can produce a filter with extra `~ # | ( )`).
- **No floats for money or quantities**: `Decimal` end-to-end, `numeric` columns, decimals as strings in JSON; CI step
  fails on `float(` in `app/orders`, `app/purchasing`, `app/offers`, `bridge/app` (ruff banned-api / grep).
- **Schema drift check**: CI validates every `bridge/app/queries/*.graphql` against `bridge/schema/graphql_schema.json`
  (`graphql-core` `validate`, ready-made script `tools/validate_graphql.py` — also checks ```graphql blocks in
  docs/); a query with an unknown field fails the build. Same for REST paths vs swagger.
- **Contract tests**: the main app talks only to the bridge; bridge mock and real client share Pydantic models and
  one contract test suite (run against the mock in CI, against TEST agenda manually with a flag).
- **Golden fixtures**: extraction (orders, invoices) compared to `expected.json`; confirmation/clarification e-mails
  as snapshot tests; print documents (offer, order confirmation) rasterised and compared with
  `fixtures/documents/*.png` (pixel diff < 0.5 %, fails when Arial Narrow / Liberation Sans Narrow is missing);
  any change in output must be reviewed.
- **Idempotency & concurrency tests**: double approve, timeout after mutation, reconciliation, two users editing the
  same draft (optimistic lock 409).
- **Strict typing**: mypy strict for `app/` and `bridge/`, `tsc --strict` for web; no `Any` in money/order code.
- **Shadow mode per feature** (feature flags): new write features (supplier import, orders) first run in shadow mode —
  drafts are created, the create button is hidden, and a nightly job compares drafts with documents people created
  manually in Money (same customer + `Odkaz` / same supplier + number) → accuracy report in Admin; switch on only
  after the agreed threshold (orders: 2 weeks, ≥ 95 % lines identical in article, quantity and price).
- **Observability**: every log line of a document flow carries `draft_id`/`suggestion_id`; Sentry for exceptions;
  no mail bodies or Money payloads in logs.
- **Definition of done per phase** = acceptance criteria + all gates green + README/CHANGELOG + list of open risks.

## 1. Goal
Responsive web app + installable PWA for 3–10 users. Reads/sends company mail through the existing IMAP/SMTP server
(the one Roundcube uses), keeps Roundcube's structure and wording, classifies mail with AI, prepares replies and
actions, works with Money S4 through its API module (GraphQL + REST): find & send invoice PDFs, receivables &
reminders, received delivery notes created from supplier invoices/delivery notes with automatic item matching to
stock articles (received invoices are NOT handled — DECISIONS D7), customer orders (no stock handling, D6),
complaints, customer card with prices, CRM activities; offers created in Money (D5), assistant chat, morning briefing.
HARD RULES: AI never sends e-mail outside the company and never writes to Money on its own (max autonomy level 2 for
those actions). Every external send and every Money write requires an authenticated user's approval; the backend
re-runs all checks at approval time. Mail keeps working when Money or the AI provider is down.

## 5. Mail layer
IMAP/SMTP of the existing server (Roundcube's), TLS, password or XOAUTH2. Incremental sync (UIDVALIDITY+UID,
CONDSTORE/QRESYNC if available), IDLE on INBOX (re-IDLE 25 min) + 2-min poll for all other subscribed folders. Server-side filters (Sieve) move
mail into the customer's own folders (e.g. Nitra, Senica, Trenčín, Dodávatelia, Faktúry, Kurier — DECISIONS D21), so
the AI pipeline processes new mail in **every subscribed folder** except Koncepty, Odoslané, Kôš, Nevyžiadaná pošta
and folders marked private; a folder can be mapped to a branch (SETTINGS 11a). SPECIAL-USE folder
mapping with Roundcube SK names. Threading: References/In-Reply-To, fallback normalized subject + participants (30 days).
Flags round-trip (\Seen \Flagged \Answered \Deleted, keywords `$SmartDone`, `$Forwarded`). Send via SMTP, APPEND to
Odoslané, correct Message-ID/In-Reply-To/References. Undo-send = delayed job (default 10 s). Scheduled send = job.
Sieve: list/edit/activate scripts via ManageSieve (Filtre, Mimo kancelárie) — keep Roundcube-compatible script names.
QUOTA shown in the folder column. Drafts autosave to Koncepty every 30 s.

## 7. Money S4 (details: docs/MONEY_API.md)
Only the bridge talks to Money. GraphQL (`POST /graphql`, filters `Field~op~value`, `#` = AND, `|` = OR, `ChangeFrom`
for delta sync, no server-side ordering) for documents, address book, catalog, supplier codes (`ArticleSuppliers`),
stock (`WarehouseStocks`), customer prices (`ProdejniCeny`), codebooks; REST only for PDF reports, persons, activities
and proformas. Token `POST /connect/token` (client_credentials, `scope=S5Api`). Main app ↔ bridge: HMAC; writes need a
single-use approval JWT. Before Phase 3: copy schema files to `bridge/schema/`, read `probe_output/report.md`.
Never guess enums or GUIDs — use codebook queries or template documents. Idempotency marker `SMID:<id>` in
`Poznamka`; never auto-retry mutations; Smart Mail never edits existing Money documents (Edit replaces all items).
Core purchasing flow (DECISIONS D7 — only the received delivery note is written): supplier invoice or delivery note →
item matching cascade (supplier code → learned mapping → EAN → our code → open purchase order → fastener attributes →
user) → `CreateReceivedDeliveryNote` with `ObsahPolozky { Artikl_ID, Sklad_ID }`. Never `CreateReceivedInvoice`. The received delivery
note is reviewed on W6h, a copy of the Money card, with the exact field mapping of DOCUMENTS_SPEC §2 (Doklad prijatý =
`Odkaz`, enum-like IDs copied from the branch template document, item name/catalog = Money article, supplier code in
`PartnerskyKod`). **Every Money write uses
the document's branch: `Stredisko_ID` (header + items), branch warehouse, branch price list `Cenik_ID`, branch series
(MONEY_API §5.5.9); missing branch settings block the write.**
Customer orders (ORDERS_SPEC): extraction → customer + duplicates (`Odkaz` = customer PO, SMID) → matching cascade
(offer → our code → learned customer code → Money `PartnerskyKod` history → EAN → catalog → history text →
attributes) → `ProdejniCeny` / offer price → review W6f (no stock check, no packaging rounding — D6) →
`CreateReceivedOrder` (items: branch warehouse) → read-back →
confirmation e-mail. Never `EditReceivedOrder`; changes/cancellations = diff + task + reply.
Offers (D5): created in Money with `CreateIssuedOffer` and numbered by Money — Smart s.r.o. arranges `IssuedOffer` in the
API; the offers phase starts only when the probe finds it. PDF = Money report if available, else the Money-style
template (DOCUMENTS_SPEC §4) with the Money number; accepted → `CreateReceivedOrder`.
Issued invoices are never rendered by Smart Mail — only the original Money PDF (REST report) is attached.
Read cache (companies, persons, articles, article suppliers, price history, codebooks) refreshed every 15 min via `ChangeFrom`.

## 8. Approval workflow
`POST /api/suggestions/{id}/approve` (optionally with edited payload) → re-run all checks → 409 with details on any
blocking failure → execute (send via SMTP with undo delay / bridge write with approval token) → store final payload +
diff → audit_log → follow-ups (activity log in Money after send if linked & enabled; thread status). Batch approve:
`POST /api/suggestions/approve-batch` only for suggestions marked `batch_safe` (all checks green, confidence ≥ 0.9,
allowed types). Reject stores optional reason chips.

## 11. Security (mandatory)
No auto external send, no auto Money writes. Recipient/document-owner check on every Money document. Secrets only via
env/secret files; mailbox and token secrets encrypted at rest (Fernet `APP_ENCRYPTION_KEY`). HTML sanitized, remote
images blocked by default, links show real target. ClamAV before processing attachments. Strict CSP, HSTS, secure
cookies, CSRF, login rate limit (per account and IP; IMAP auth failures count), TOTP optional for admins, session
timeout 12 h or "Zostať prihlásený" 30 days on trusted devices, re-auth for admin actions, switching person is logged
(no PIN, D9). Audit log
append-only. pip-audit + npm audit in CI. Prompt-injection fixtures must pass. Logs never contain mail bodies or
Money payloads. Backups encrypted, restore tested.
