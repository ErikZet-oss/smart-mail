# DECISIONS.md — scope decisions of Smart s.r.o. (v2.10, binding)

Decisions D1–D10 taken by the customer on 25 October 2026, D11–D22 on 26 October 2026; D23–D24 close the contradictions found while drawing the Figma file (v2.10). They **override any older text** in the other spec files; the
specs were updated accordingly — if you still find a contradiction, this file wins and you report the contradiction.

| Id | Decision | Consequence for the build |
|---|---|---|
| D1 | No "simple view" (Jednoduché zobrazenie) for now. | Only the existing options stay: list density Kompaktná / Pohodlná and "Klasické zobrazenie". Do not build another view mode. |
| D2 | E-invoicing (eFaktúra, Peppol, from 2027) is not part of this project for now. | No Peppol/eFaktúra integration. Keep the document source abstraction (`documents.source`) open so a source `einvoice` can be added later; nothing else. |
| D3 | The customer's `fa_pdf` package is **not used**. The AI reads supplier PDFs directly in the app. | Remove `InvoiceExtractor`/`fa_pdf_adapter`. Extraction = ISDOC/UBL XML (deterministic, if attached) → PDF text layer (pdfplumber tables) + LLM → scan/image: OCR + LLM vision. |
| D4 | Warehouses in Money: **10 Trnava, 20 Senica, 30 Nitra, 40 Trenčín** (Money list of warehouses). Price lists are in the Money list of price lists. | Branches = these four. SETTINGS 11e: warehouse, price list (and centre, series) are dropdowns loaded from Money — never typed. Sample content and Figma use these branches. |
| D5 | **Offers are numbered by Money.** Smart s.r.o. will get `IssuedOffer` (Nabídka vydaná) added to the API. | Offers are created in Money via `CreateIssuedOffer` and get the Money number (PV…). No own offer series in Smart Mail. The offers module (Phase 6) starts only after `IssuedOffer` is available on the server (probe checks it). PDF: original Money report if the implementer adds a report endpoint, otherwise the Money-style template in `templates/print/` with the Money number. |
| D6 | **A customer order is written to Money as Objednávka prijatá — stock is not handled and quantities are not rounded to packaging.** E-shop orders go to Money directly. | No availability check, no stock status, no shortage decisions (backorder/partial/substitute), no reservation, no packaging rounding. Items carry the branch warehouse only because Money needs a warehouse on a stock item. E-shop e-mails are ignored (never create an order draft). Prices stay: offer price / customer price from Money (`ProdejniCeny`) / manual. |
| D7 | **Goods from suppliers: only the Dodací list prijatý is written.** The received invoice (Faktúra prijatá) is not handled by Smart Mail. | Purchasing = supplier invoice or delivery note → item matching → `CreateReceivedDeliveryNote` (DOCUMENTS_SPEC §2). No `CreateReceivedInvoice`, no Mode A/B, no supplier proformas, no IBAN/payment checks, no "Faktúry prijaté" tab and no invoice review screens. The supplier invoice PDF is only the source of the lines. |
| D8 | **AI permissions are set by each login itself** in its settings. | Settings 07 "AI asistent": autonomy per action is set per login (account); there is no admin maximum. The hard limits in code stay and cannot be changed by anyone: sending e-mail outside the company and every Money write always need a human approval (autonomy ≤ 2 for these actions). |
| D9 | **No PIN.** | Remove PIN from branches, persons, "Kto ste?" and settings. Clicking a name selects the person. |
| D10 | Names, functions, signatures etc. are added, edited and deleted by the customer in Settings. | Settings 11 (Pobočky a osoby) is the only place to manage persons and signature templates (create / edit / delete with confirmation). No import obligation; the Roundcube import of identities stays optional. |
| D11 | **Warehouses = the Money list of warehouses: 10 Trnava, 20 Senica, 30 Nitra, 40 Trenčín, 99 Externý sklad.** | 10–40 are the branch warehouses. 99 is not a branch: like every warehouse it appears in all warehouse dropdowns (D18), but it is never a default and never chosen automatically. All warehouse values come from `Warehouses` at runtime — **never hardcode codes or GUIDs** (the TEST agenda may have other IDs). |
| D12 | **Price lists = the Money list of price lists**: per branch a pair `10-bez DPH` / `10-s DPH`, `20-…`, `30-…`, `40-…` ("Trnava bez DPH", "Trnava s DPH" …), plus `13 PKT`, `99 Externý sklad`, `A1 - 100%`, `A2 - 70%`, `A3 - 30%`, `MPC Minimálny predajný cenník`. | SETTINGS 11e "Cenník pobočky" is a dropdown of `PriceLists` (label `Kód – Názov`, search). Sample content: Senica = `20-bez DPH – Senica bez DPH`; the dropdown always lists all price lists. No business logic depends on individual price lists such as A1–A3, 13 PKT or MPC (D18). Customer prices still come from `ProdejniCeny` (Money calculates them). |
| D13 | **Stock movement date and time on the received delivery note = the moment Smart Mail writes the document to Money** (approval). | `DatumSkladovehoPohybu` + `CasSkladovehoPohybu` = approval time (Europe/Bratislava), `DatumUcetnihoPripadu` = same date. Read-only on W6h ("pri zápise do Money" before create). No fixed time, no setting. `DatumVystaveni` stays = date of the supplier document. |
| D14 | **Fees on supplier documents (doprava, balné, palety …) are not handled for now.** | Never written to Money. Tab `Poplatky` on W6h lists them read-only with "Poplatky sa nezapisujú – ak treba, doplňte ich v Money"; warning DL-W5 stays; `Náklady` button not shown; SETTINGS 14 shows it as info only. |
| D15 | **Returns (vratky) are done only in Money.** | No negative quantities in Smart Mail (DL-B8 blocks), `Vratka` checkbox read-only unchecked. |
| D16 | **New logo of Smart s.r.o.** (blue wordmark "SMART"; vector original from Adobe Illustrator, print colour CMYK 85/50/0/0, screen colour `#0F75BC`). | App brand colour `brand/primary-600` = `#0F75BC` (UX_SPEC §2, `design/tokens.json`). Files in `design/brand/`: `logo-smart.svg` / `logo-smart-white.svg` (from the vector), PNG exports and the app icon set `app-icon/` (PWA 192/512, maskable, Apple touch, favicon "S") generated by `make_icons.py`. Print PDFs (offer, order confirmation) keep the logo of the Money report until Smart s.r.o. changes it in Money (`templates/print/assets/logo.png`, SETTINGS 16). |
| D17 | **No packaging rounding anywhere** — neither in orders (D6) nor in offers. | Quantities stay exactly as the customer wrote them (after unit conversion). The offer line may show the package size as information ("bal. 200 ks"), but never changes the quantity; no "rounded" hint, no automatic rounding, no rounding tests. |
| D18 | **All price lists and all warehouses from Money are shown — the user picks the right one.** No filtering, no "branch only" lists, no interpretation of individual price lists (A1–A3, 13 PKT, MPC …). | Every price-list or warehouse dropdown (SETTINGS 11e, W6h line warehouse, offer stock information) lists the complete Money codebook (`Kód – Názov`, search box). Settings "Ďalšie sklady" and "Sklady pre dostupnosť" are removed. A line warehouse that is not the branch warehouse is only a warning (DL-W8), not a block. Offers show stock of all warehouses as information. |
| D19 | **Reference look = the customer's Roundcube** (Elastic skin, screenshots of 26 October 2026, anonymised copies in `design/reference/roundcube/`). | Layout, labels and order follow the screenshots: no global top bar on the mail screen (each column has its own header); rail bottom Tmavý režim · O systéme · Odhlásiť; list header Výber · Konverzácie · Možnosti · Obnoviť; list in "Zoznam" mode with pagination "Správy: 1 – 50, z …"; reading toolbar Odpovedať · Odpovedať všetkým · Poslať ďalej · Vymazať · Nevyžiadané · Označiť · Viac (Archivovať is in Viac); compose toolbar Uložiť · Priložiť · Podpis · Odpovede, "Odoslať" under the editor, right panel "Možnosti a prílohy"; settings order Nastavenia · Priečinky · Identity · Odpovede · … ; quota as a bar with %; login with icon fields and a full-width button. Details: UX_SPEC §4, SCREENS_SPEC G1–G3, W1, W2, W4, W12. |

| D20 | **"Nastavenia e-mail schránky" are the hosting provider's settings** (mail2.nameserver.sk: info o schránke, zmena hesla, presmerovanie, ostatné nastavenia, automatická odpoveď, GEOIP ochrana). | Smart Mail keeps the section with the same name and place (SETTINGS 09b): read-only info it knows + a button to the provider's administration (URL set by the admin in SETTINGS 12). No own password change, forwarding or GEOIP — no API. Automatická odpoveď = use Mimo kancelárie (Sieve), never both. |
| D21 | **Folders like Nitra, Senica, Trenčín, Dodávatelia, Faktúry, Kurier are the customer's own folders filled by server filters** (by sender). | They stay exactly as they are (Filtre edit the same Sieve scripts). The AI processes new mail in all subscribed folders, not only Doručená pošta; a folder can be assigned to a branch (SETTINGS 11a "Priečinky pobočky") so suggestions from it get that branch. |
| D22 | **Signatures are HTML like in Roundcube, with a source-code view** to paste own HTML and images. | Signature editors (SETTINGS 03a, 11c) = WYSIWYG + `<>` Zdrojový kód + Vložiť obrázok (upload ≤ 200 kB or https URL). Uploaded images are sent as inline CID parts (shown without "load remote images"); URLs stay as links. HTML ≤ 64 kB, sanitised (no scripts/forms/iframes), variables like {meno} work inside the source. Plain-text version generated automatically. |
| D23 | **Contradictions found in the Figma design are closed as drawn in Figma** (26 October 2026). | (1) Order confirmations never promise stock or delivery from stock (fixture fixed, D6). (2) Sample washer quantity 2 450 ks everywhere (D17). (3) Document numbers are Money numbers, sample format `OP263101` / `PV263415` — never `OP2026/0457`. (4) One `BranchChip`: full "Pobočka Senica · Stredisko 20 · Cenník 20-bez DPH · Sklad 20" in page headers, short "Pobočka Senica · stredisko 20 · sklad 20" in lists and cards. (5) No `orders/availability.py`; offers keep `stock_info` (information only, D18). (6) Received delivery note warnings are DL-W1–W8. (7) Warehouse 99 is in every list but never a default. (8) W6h header ≈ 450 px (Money field layout). (9) Sample users are fictional: Peter Hudák, Jana Nováková, Marek Kováč, Eva; "Schváliť všetky bezpečné (3)". |
| D24 | **The Figma file is the visual source of truth** (https://www.figma.com/design/vBDv8OCQTjxPBMzq6KBcHU). | Every screen ID has its frames in `docs/FIGMA_MAP.md`; the coding agent reads them through the Figma MCP server before building a screen. Look = Figma; behaviour, texts and rules = specs (this file first). A disagreement on behaviour is reported, not silently resolved. |
